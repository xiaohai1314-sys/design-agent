# 上下层楼梯与挑空

先按附件名称和踏步位置确认上下层。梯位不改时，同一梯井和各层落脚区都沿原图，直接生成需要调整的楼层。照原图定位挑空边，保留未纳入改造的露台上空；新楼板、净高、采光及入室方式逐项对照。未证实的结构改动按拟改说明。

本页后续坐标与回执流程用于新定共用梯位、原图跨层对应难以判断或明确要求精确几何保护的任务。两张纸图照片用下面命令生成并排坐标页，已有原图坐标时直接取点。

```text
python -B -X utf8 "<Skill 路径>/scripts/stair-pair-guide.py" --lower-image-path "<下层原图>" --upper-image-path "<上层原图>" --coordinate-sheet-path ".design-agent/两层坐标.png"
```

按图名认清上下层，圈出拟封的挑空并保留露台上空。原梯可用时，两层直接沿用并核对到达。原图缺梯时，确定共用梯位、方向和两层各自的进出路线，再布置主卧、客厅和家具。上层落脚应能到卧室或过厅，并避开拟封楼板边缘。其余墙、窗、室外边界及上下水沿用原图。

用 `write_file` 写配对文件，`execute` 每次直接运行一个 `python -B -X utf8` 命令。先确认各层改动范围。只需保留原布局并加梯的楼层填 `"retainLayout":true`，实际需要新排的楼层填 `"retainLayout":false`。读同名结构并用 `--check-anchors` 核对。看到带斜线的井道或未标区域时，从上下两图的踏步和入出口确认现状。

## 同一个梯井标到两张原图

用两层相同的外墙折角、同一柱角或同一分段尺寸链对应的轴线交点。先用房间旁的尺寸数字辨认同一轴段，再读取坐标。三对定位点尽量分布在改动区周围，两层按相同对应顺序填写，第四对用另一侧独立交点。排除楼层不同的隔墙和名称、纸边、页脚。同一角点不清时，在已有坐标页确定区域，用 `--lower-regions-path` 和 `--upper-regions-path` 同张放大对应处。格式为 `{"regions":[[左,上,右,下]]}`，坐标仍用原图像素。直接填写首份配对数据并跑预检，按返回的偏差核对具体点位。梯井多边形只在下层填一次。起步和落脚各自填在所在层可站立的位置。

纸图变形、两层改动大或四点首检超差时，在两层 `image` 和 `anchors` 填五至八组候选，按同名特征一一对应。用 `--pair-path ".design-agent/stair-pair.json" --check-anchors` 一次检查。返回 `anchor_selection_ready` 时，参照 `checks` 核对原图上有偏差的编号，确认推荐的四组确实是同一墙角或轴线，且覆盖梯井周围。将 `lowerAnchors` 和 `upperAnchors` 原样替换到最终配对文件，再补梯井、平台和墙柱。返回无可用组合时，只重看有疑问的一处原图局部。四点本身清楚时，沿用三组定位点和第四组独立核验点，可直接做完整预检。

```json
{
  "stairType":"straight",
  "lower":{
    "image":"<下层原图>","anchors":[[110,180],[860,180],[110,820],[860,820]],
    "retainLayout":true,
    "locks":[{"points":[[380,450],[405,450],[405,720],[380,720]]}]
  },
  "upper":{
    "image":"<上层原图>","anchors":[[135,170],[885,170],[135,810],[885,810]],
    "retainLayout":false,
    "locks":[{"points":[[405,440],[430,440],[430,710],[405,710]]}]
  },
  "lowerEditRegion":[[430,380],[800,380],[800,790],[430,790]],
  "upperEditRegion":[[455,370],[825,370],[825,780],[455,780]],
  "footprint":[[640,470],[730,470],[730,700],[640,700]],
  "lowerLanding":[685,426],
  "upperLanding":[710,738]
}
```

上例下层保留原布置、上层新增房间。用户要上下层布局图、只指定上层的房间改造时，下层用带梯位的沿用图交付。调整梯井或起步点时继续沿用各层已定的范围。该层确有房间或家具要重排时才在该层填 `"retainLayout":false`。

```text
python -B -X utf8 "<Skill 路径>/scripts/stair-pair-guide.py" --pair-path ".design-agent/stair-pair.json" --output-directory ".design-agent/stairs"
```

`stairType` 填 `straight` 或 `turn`。命令检查完整梯段与两端后，返回 `fixed_stair_ready` 和可送生图的 `imageGeneration` 清单。只复查几何时用 `--check-only`。只标位置的方案讨论可省略 `stairType`，得到 `stair_position_marked` 阶段图。两层分别填写可改净区。纸图去除留白可在各层对象填 `generationCrop: [左,上,宽,高]`，确认包含楼梯、落脚、周边墙窗和需要设计的房间。贴回仍用原图和回执中的裁切范围。

拟封挑空新增梯井时，从上层原图沿允许开洞区域的净边界填 `upperEditRegion`，例如 `[[400,450],[740,450],[740,720],[400,720]]`。边界沿保留墙内侧画。把附近仍须保留的墙柱分别写入两层对象的 `locks`，用 `[{"points":[[400,450],[420,450],[420,520],[400,520]]}]` 这样的原图多边形。脚本会拒绝跨出净区或盖住已登记构件的梯井。看回执底图和原图，确认梯段连线没有压过墙、柱和开口。第四点超差先按报错用原图坐标复核一次。仍无法对齐时，在原图可确认的局部完成布局，给出梯位待定位的图面说明。此时优先出能完成的房间，涉及跨层交通的可改区保留为梯位待核，避免各层独立生成楼梯。只有实物尺度、踏步及梁下净高能核时才能确认梯段可落地。

生成固定梯位前，两层都填可改区和 `locks`。拟留用的门和墙在首轮回执前标齐，保护项可位于改区边上或外侧。生图后沿用同一份配对文件。

梯位回执通过后，先看各层 `approachOnSource`。出现 `line_across` 时，放大原图确认该线是墙、梁、窗轨还是楼板边线。能在同一可改区选到无遮挡的落脚位置时优先调整梯位。确需新开口而构造未确认时，在图上明确拟开口位置和条件，保留可评审的房间方案。

按回执的 `imageGeneration` 清单调用 `generate_image`，并把返回路径填进 `candidateBatchTemplate` 对应楼层。只要求上层封挑空新增房间、原下层能到起步时，下层已填 `"retain"`，只对上层图生图。提示词写受改房间、隔墙、门位、梯井方向和起落端。用回执裁幅和二维正投影。候选返回先贴回，再从下层入户走到起步、从上层落脚走到目标房。新增楼板、梯段、栏杆及实际净高按结构和现场深化。

## 新增直跑梯的固定底图

白底或浅底、两层可改区能核实时，可把规划的直跑梯画进两张底图。把 `lowerEditRegion` 和 `upperEditRegion` 分别按本层可改净区填写。梯井依次填写起算短边的两角，再沿长边填写远端两角。先沿下层入户到梯端、上层对面梯端到目标房确定走向及转角，再放家具。起步和落脚分别填在相对短边外的可站立面内，沿梯段宽度向外延伸定位。脚本会检查点位与梯段短边的位置，并核对短边到落点之间是否压住已标记墙柱。平台深度、门扇和家具外廓按原图及实测核对。没有可靠尺寸时在原图上画出连续留空的范围，供同一底图引导和终稿检查。

在同梯井引导命令上加 `--draw-straight-stair`。两层分别输出 `layoutBase`、`layoutBaseSha256` 和 `stairLock`。用对应 `layoutBase` 作为生图底图，明确唯一的跨层梯段及其两端净空，写清梯段两侧的房间和各自的门位。踏步符号用于表达方向与衔接，数量按实测层高及踏步深化。

纸图照片有大块纸边或原图文件较大时，可在各层对象加 `generationCrop: [左,上,宽,高]`，保留整层布局和四周可对位的墙窗。回执会增加 `generationImage` 和 `generationCrop`。发送 `generationImage` 生图，合成仍用无损 `layoutBase`，并加 `--reference-crop-path` 指向回执中的 `generationCrop` 文件。

按[固定底图编辑](locked-plan-edit.md)贴回可对位候选。两层分别将 `layoutBase` 同时作为 `--base-path` 和 `--original-path`，复核 JSON 的 `originalSha256` 填该底图哈希，`locks` 加入该层 `stairLock` 并保留原建筑保护区。贴回前核对可改范围包含完整门扇、墙端和家具。候选重画梯段时，保住原定梯段并清除新增踏步、箭头及残线。成图沿入户到下层起步、上层落脚到主卧门走一遍，再对照两层原图核对可改区外的保留项。候选无法对位时说明尚待确认的房间、门位或到达路径。提交已有的可评审楼层方案和定位底图，并标明阶段状态。

## 复查准备登记的图

候选一返回，按工具返回顺序写 `{"lower":["<下层候选1>","<下层候选2>"],"upper":["<上层候选1>","<上层候选2>"]}`。先做贴回，再查看实际结果。只返回一张时写一个路径。

题意只要求上层新增房间，下层只需安置新梯且现有入户路线能到起步时，下层直接沿用，写 `{"lower":"retain","upper":["<上层候选1>","<上层候选2>"]}`。有固定梯回执时，工具会返回下层原图加已核梯位，并生成同页坐标，供实际复核和登记。下层也要重排时传下层候选。下层贴回失败且原布局实际可用时，可改用 `retain`，从已返回的候选中复用上层。两张图登记后，如实说明沿用的楼层及需要核实的平台、结构及净高。

```text
python -B -X utf8 "<Skill 路径>/scripts/stair-pair-guide.py" --pair-path ".design-agent/stair-pair.json" --candidate-batch-path ".design-agent/两层候选.json" --fixed-stair-receipt-path ".design-agent/stairs/fixed-stair.json" --output-directory ".design-agent/贴回两层" --delivery-directory "跃层平面方案"
```

工具逐层先试首选，无法对位才试同批备选。固定梯已在合成中逐像素保留，命令直接复用原来的梯角和起落点做终检。打开两层 `verifiedPng` 和 `coordinateSheet`，按 `sourceProtection.seamsToReview` 复核新线在贴回边缘是否截断房门、床或房名，再走实际通路。可从同批备选中换图，家具出界时优先在允许范围内补齐家具。终检报告横线或对位失败时，检查对应楼层和位置；只有可完整使用的布局才登记为完成。阶段交付用已贴回的 `image`，注明阶段状态和实际缺口。

新增 L 形梯用 `--draw-turn-stair` 固定两层同一梯井。六点从下层起步端短边的一角开始，顺次经过凹角、上层落脚端短边两角、外转角，再回到起步端的另一角。示例 `[[640,600],[790,600],[790,460],[880,460],[880,700],[640,700]]`，下层起步点取第一条短边之外，上层落脚点取另一短边之外。按实际净区和保留墙柱取点。脚本检查两端与各自梯段方向相接及进出平台避开已标墙柱。

出图用回执的 `generationImage`，无裁幅时用 `layoutBase`。提示词将梯段写成底图里的固定构件，写清上层房门到既有落脚点的连接，家具避开两端。批量贴回加 `--fixed-stair-receipt-path ".design-agent/stairs/fixed-stair.json"`，让两层直接保留底图上的梯段和起落端，室内布局按已确认的区域贴回。打开合成图检查梯段以外是否有多画的踏步、墙或家具，再沿两层通路走一遍。终检仍用用户原图和实画梯口。图上的阶梯线用于表达走向，实际踏步数、楼板、平台与净高待复尺。

需要人工同名点或只贴回一层时，按[固定底图编辑](locked-plan-edit.md)单独贴回。固定直跑梯可先贴回画好梯段的底图，以下最终复核仍用用户原图，原图中允许新增梯段的位置列入改区。

已另做人工贴回或局部修图时，给实际准备登记的两张整幅 PNG 各取同样四个结构点、实际梯井边界和对应可站立点。另存 JSON，仍用 `lower`、`upper`，每层填 `image`、`anchors`、`footprint`、`landing`、`protectionReview`。梯井各点取成图上实际可见的同一角。`protectionReview` 指向该层原图坐标的复核 JSON，含用户原图的 `originalSha256`、`edits`、`locks`。

```text
python -B -X utf8 "<Skill 路径>/scripts/stair-pair-guide.py" --pair-path ".design-agent/stair-pair.json" --candidate-check-path ".design-agent/stair-reviewed.json" --fixed-stair-receipt-path ".design-agent/stairs/fixed-stair.json" --delivery-directory "跃层平面方案"
```

未使用固定梯底图时可省去 `--fixed-stair-receipt-path`，直接在图上核对梯口。固定梯终检会在同一坐标比对原图与成图的进出端。若报告有贯穿线，打开该层定位并在已确认可改范围内复核；照片纹理等疑似干扰也在此处人工辨认。

通过时返回两层各自的 `verifiedPng`。打开核对门墙、踏步方向和两条实际路线。下层从入户到起步，上层从落脚到主卧，梯井与卧室之间要有连续隔墙和可关合入口。仍有影响通行或围合的缺口时说明具体待核处。提供可评审的房间图与梯位图，并标明阶段状态。
