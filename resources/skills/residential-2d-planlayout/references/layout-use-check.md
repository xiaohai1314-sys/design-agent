# 连续通路与使用检查

用初稿的实际图元核对本轮要求及受影响的局部。先看原图和成图、用已有尺寸核算。需要验证绕行或多处障碍时再用工具，核对范围包含入口、转角或瓶颈的两侧。

## 原图坐标视图

首次读取原图后，单独运行下面这一条命令。返回路径、原图尺寸及哈希。打开返回的 PNG，用四个带原图坐标刻度的分区定位墙端、入口、分隔和转角。刻度标签可直接用于 `review.json`，哈希填入 `originalSha256`。刻度图用于取点，生图使用原图和通过预检的引导图。

```text
python -B "<Skill 路径>/scripts/plan-coordinate-view.py" --input-path "<原图>" --output-path "source-coordinates.png"
```

已确认有实心墙柱可作为保护依据时，同一命令加 `--scan-filled`。结果包含底图明暗及扫描候选编号和矩形。对照原图确认墙柱、应保留符号及可改图元，再用[固定底图编辑](locked-plan-edit.md)保护相应填充、细窗线与接缝。

从原图已能圈出几处待确认的墙端或门轨时，直接写一份 `{"regions":[[左,上,右,下],[左,上,右,下]]}`，在同一命令加 `--regions-path "focus.json"`。坐标为原图像素，右和下为不含的边界。最多四处组成一张带细刻度的放大图，一次核对入户、需保留的门扇和拟改分隔。已有全图坐标足够时直接用全图写复核文件。

直接写最小的复核 JSON，`edits` 圈本轮需要布置的净区，`locks` 圈保留的墙柱和完整门窗。保留路线填 `existingRoutes`，新建闭环填 `plannedCircuits`，要核的开口填 `crossings`。先写一次并运行引导命令。预检报某一点、门洞或断段时只复查对应位置。

## 位图门洞复核

先放大实际候选图，对照原入户、墙端和门垛。门扇要落在两个有效墙端之间。沿墙厚穿过门洞，核对墙两侧的站立、开门与连续通行。窗线、屏风、柜体和柱都可能切断箭头所示的路径。标注洄游时，沿两个不同的真实开口走完整个闭环。标注路线的方向以图纸里的实际空间关系为准。

对高对比线稿，局部开口难辨时，可用[读图脚本](../scripts/check-plan-apertures.py)辅助确认横跨通路的线条。用带 OpenCV 和 NumPy 的 Python 执行 `python "<Skill 路径>/scripts/check-plan-apertures.py" "成图.png" "门洞采样.json"`。深底浅线图加 `--dark-background`。脚本只读取图像。

```json
{"crossings":[{"id":"厨房门","from":[182,190],"to":[182,213],"width":62}]}
```

`from`、`to` 紧贴同一门洞两侧墙面，垂直跨过墙厚，勿拿远处转角当采样端点。`width` 是沿墙方向的采样宽度，至少 12 像素且不小于跨墙长度。例如跨墙 20 像素、沿墙采样 32 像素。怀疑门扇悬空时，可加 `wall_support` 数组，沿可疑门垛外侧的同一墙段取样。

- `line_across` 表示采样带有连续横线，放大区分墙、窗、柜与门槛、导轨等符号。`wall_end_unverified` 表示在指定位置找不到足够连续的墙线，复核门扇是否属于这段墙。
- `clear_sample` 只说明采样带局部有空白，需结合图上门垛与完整路线判定。`review_sample` 表示局部线条需要目视核对。彩平、底纹、标注和低清图优先直接放大核对，不据阈值下结论。

[原图和开口校验](locked-plan-edit.md#登记前核对)可用 `routes` 检查高对比线稿上的连续通路。每条含 `id`、瓶颈两侧的 `from` 和 `to` 像素坐标、`widthPx` 和 `areas`。`areas` 用若干 `{"points":[[x,y],...]}` 多边形限定该路线可经过的区域，双动线分别圈定各自通过的开口和转角。脚本按线条间的可通行像素检查连通，文字和门扇图例也可能触发复核。放大核对家具、门扇和实际使用，毫米净宽按可靠尺寸依据核算。

要求保留原有路线时，在同一个复核 JSON 写 `existingRoutes`。例如 `[{"id":"玄关经走廊到客厅","points":[[190,200],[190,266],[380,266]],"widthPx":24,"reservedWidthPx":28}]`。起终点放在实际出发和到达空间的可用净空内，各中间点放在门洞、转角和瓶颈。两个出口最终到达同一公共区时，两条路线都要追到公共区。`widthPx` 是检查的通行宽度，按题设或原图瓶颈净宽取值。`reservedWidthPx` 是留在原图上的保护带宽度，缺省比通行宽度多四像素。合成会从中心线生成保护区及对应路线，检查端点和各中间点连通。原图不连通时先核对端点、转角和图例。已用中心线定义的路线可直接沿用，无需另画相同的 `locks` 和 `routes`。从图面确认两条路线确有不同的开口或绕行段。

生图前先核对路径在原图可用。Windows cmd 可运行以下命令，成功只返回路线名称，完整保护带由合成命令计算。

```text
python -B "<Skill 路径>/scripts/compile-plan-requirements.py" "<原图>" "<复核 JSON>" --check-existing-routes
```

需要保留两个既有出口时，设 `"distinctRouteExits":true`。用 `crossings` 各取一个横穿真实门洞的短采样带。每条 `existingRoutes` 写入按顺序经过的 `crossingIds`，第一项为玄关出口。用 `destinationRect:[左,上,右,下]` 表示实际使用区内可达净空。例如餐厅取餐桌实际可接近的一侧，客厅取能到沙发前的通带。两个出口绕行后确实到达同一处时，可以共用终点。中心线要穿过各开口并走到使用区。布置鞋柜、桌椅和门扇时按完整占位避开两条路线。沿用首轮位置及净宽。

复核既有通路失败时，`blockedWaypoints` 给出卡住的原图坐标和到最近图线的距离，`segmentsNeedingReview` 指出断段。打开同一次合成的局部复核图，从对应点检查门扇、家具和文字。带底色的 CAD 截图优先保留原底色，局部色差可随图说明。清除残线或移开挡路家具时只处理相应局部，再按原回执复核。

需出首轮引导时，下方命令会运行原图预检，再用同一份 JSON 生成橙色通路引导图与回执，可以直接替代上面的单独预检。

预检通过时，回执旁同时保留同一份原始复核 JSON。合成可直接传 `--route-receipt-path`，由工具按哈希读取留存的范围。即使工作 JSON 后来被编辑，实际送过的引导仍用自己的回执。只有原图确认了位置误读并重新出图时，才使用与新引导对应的回执。

原入户及要保留的墙窗也需在这份 JSON 中标出保护区。可用 `planPoints` 的 `preserve` 矩形抽查原入户和窗段，预检会检查它们有没有落进可改区。合成会使用自动实心保护时，原图预检也可加 `--add-filled-locks`。

```text
python -B -X utf8 "<Skill 路径>/scripts/annotate-plan.py" --input-path "<原图>" --geometry-path "<review.json>" --output-path ".design-agent/route-guide.png" --route-receipt-path ".design-agent/route-receipt.json"
```

把 `--output-path` 写出的引导 PNG 作为唯一平面参考。写明通路的出口、终点及邻近家具的落位。桌椅靠近双动线终点时，用 `planPoints` 的 `rect` 圈整套餐桌及座椅（含拉出余量），加 `"showOnGuide":true`。预检查整个矩形，图上只标四角。家具和门扇避开通行带，成图移除引导色。登记前沿两个实际出口分别走到使用区。

后续合成用 `--route-receipt-path ".design-agent/route-receipt.json"`。工具读取与首轮引导对应的复核范围和保护设置。需要贴回局部补图时用独立的 `--regions-path` 记录补图范围。原图确有读错时，从原图重新核定，交代修改了哪个门洞或终点，再使用重新生成的引导及回执。

## 拟建洄游检查

用户只要求有一条洄游时，选一条服务日常活动的公区闭环。优先利用已有的两侧通路或开口。餐厨可围绕餐桌或岛台布置，先确定家具连座椅的占地，再留出两侧和转角的净空。要串联两个房间时，先确认有两个不同的出入口可走。保留卧室、卫生间的独立围合和原有墙窗。拟设门洞落在可改范围，需要拆改时随图标明位置和待核条件。最后从公共空间内的净空出发，逐个经过成图上的真实开口和转角，沿另一边回到起点。

常规洄游题用原图和提示词明确开口、完整家具占地与路径，出图后沿实际开口走一遍。已按主流程判定需固定底图或引导时，可把高对比线稿的开口采样写进 `crossings`，把环路写进 `plannedCircuits`，复用固定底图的预检和校验。每条路线包含以下字段。

- `id` 为环路名称，`points` 为原图像素坐标。把首点再次放在末尾，路线沿实际行进方向依次经过门洞和转角，中途各点不重复。
- `crossingIds` 列出实际经过的墙洞。每个门洞的采样带横穿墙厚，两端选在门洞两侧的可用地面。开放式餐厨绕岛台时，只把转角写入 `points`，全程没有穿墙时 `crossingIds` 留空。
- `widthPx` 是要检查的通行净宽。`corridorWidthPx` 是每段中心线周围允许查找通路的带宽，留少量偏移余地，保持在实际路线附近，避免搜索绕进另一条支路。
- 绕家具时填 `furnitureRect:[左,上,右,下]`，圈住同一组岛台或桌椅的完整使用占地，包括需要拉出的座椅。预检把这块范围当作障碍，核对通路。彩色引导用绿色虚框，去轨黑白副本用四个浅灰短角。桌椅完整放在标记内，成图删除标记。

阳台并入、厨房开敞或其它独立的打通要求，也在 `crossings` 各写一处横穿原分隔的采样带，拟打开的分隔加 `"state":"proposed"`。只把环路实际经过的采样加入 `crossingIds`。绕餐桌时，用独立采样核对两处阳台，原厨房门能进出时保留门和两侧墙段。样带只覆盖要打开的一段。检查成图有无原轨道残留，以及门槛高差、接驳和排水哪些仍需现场确认。

先从入户沿原有门洞走到各房间，确认现有门的两侧分别接到哪里。沿用的门用 `locks` 一次圈住完整门弧、门扇、墙厚和两侧门垛。重点查入户门、卧室前室连续的几道门、厨房原门和卫浴门。只圈门扇一端会让合成截断另一端。拟建门洞先落实有依据的可改墙段，从公共通道通到房间，横穿完整墙厚登记一处 `crossings`。新增洄游优先通过家具落位解决。成图从原入户再走一遍各房门，查门弧两侧和完整墙厚。补画门扇时保留对应的墙洞净空。

对每处拟开口，在生图提示词写清两空间地面连续，去掉原分隔及轨道。用两侧墙端定位开口净区，把靠近它的家具一起限定。客厅接阳台时，写清沙发、贵妃位、边几和茶几在客厅内侧止住，整组避开门垛之间及两侧进出净空。厨房接生活阳台时，橱柜及设备从拟通开的分隔两侧退出，转角柜在开口前止住。绕桌椅或岛台时，先按用户要求的席位和可靠尺度核算整组家具及拉椅占位，再定 `furnitureRect` 和闭环。席位未指定且餐厅需要绕桌通行时，优先排四座短桌，两条长边各两把，桌端留空。席位已指定时按要求核算，必要时调整桌形、朝向或另选闭环。把座位数量、放椅边、桌端净空和完整占位标记写进生图 `query`，例如「餐区四个浅灰短角之间放一张短餐桌，左右各两把椅，前后端留空，桌椅都收在四角内，画完去掉浅灰短角」。

拟建环路核对合成后的线稿，拟增开口所在位置仍可以编辑。原有环路或入户路线的保留区仍用 `existingRoutes`。报告给出 `blockedWaypoints` 时先放大看这些点，`lineworkClearancePx` 是点到最近图线的距离。再查看仍未通过的 `segmentsNeedingReview`，沿线确认隔断、门扇和家具。像素净宽作为图面检查，有可靠定尺时再核对实际净宽。

只有一处拟开口被局部线条挡住时，合成报告可能带 `openingCleanup.repair`。看局部图的橙框。框内确认全是获准去除的分隔、重复标高或残线时，把 `repair` 保存为修正 JSON，沿用首轮回执复查。框内有原墙、家具、必要注记或未知线条时，放大定位后另作修正。图上同时核对通路以外的原厨房门和卫浴入口。

需制作带回执的首轮引导时，用同一份 `review.json` 预检。预检把可改区视为净空，保留区外和锁定区原线。拟开的门洞允许在原图仍有墙，开口位置和两侧净空要落在允许调整的范围。若报断段，按原图核门垛、固定隔墙、岛台与餐椅范围。选择能走通的路线，或准确补上获准的开口范围。保留约定的净宽和固定构件。预检通过后再传引导，并在成图复查净宽和闭环。

```text
python -B -X utf8 "<Skill 路径>/scripts/annotate-plan.py" --input-path "<原图>" --geometry-path "<review.json>" --output-path ".design-agent/route-guide.png" --route-receipt-path ".design-agent/route-receipt.json"
```

预检通过后只把 `--output-path` 写出的引导 PNG 传给首轮生图，原图留给合成与验收。提示词直接写各空间落位、拟开口两侧、桌椅朝向和实际净空。橙带留空，蓝带全部画成两空间相连的空地，保留两侧固定墙垛。成图清除全部过程色。合成用 `--route-receipt-path ".design-agent/route-receipt.json"`。空底图已确认实心填充都要保留时，生成引导加 `--protect-filled-regions`，合成继承回执设置。混有可改实心对象时，在 `locks` 分别圈出要保留的墙柱。

原分隔是清楚、确认可拆的直线门或轨道时，在对应拟开口加 `clearRect:[左,上,右,下]`，紧贴要移除的轨道线，右下边界不含在内。引导命令加 `--show-openings-cleared`，工具只擦除通过预检的门轨。`unchangedSeparators` 表示该处分隔还在。对照原图和实际引导定位残线，只修正有明确依据的范围，保留原必检开口和净宽要求。补生图前按[补救](fixed-plan.md#补救)确认问题已从输入中消除。

用户要黑白线稿且有可核定的门轨时，引导命令同时加 `--show-openings-cleared --clean-guide`。生图只传局部去轨的黑白副本，按相邻空间描述拟开口，按浅灰短角限定桌椅占位。提示词要求房名避开通路、门洞与原图尺寸标高，绕桌时餐厅名称可放在桌面内。生图返回后先合成同批候选，核对开口、闭环和引导标记残留。合成复用原图、首轮复核 JSON 和首轮回执。图面剩局部问题时先修预览中的具体家具、门扇或残线。需要更改首轮开口或闭环时，先对照原图确认读图错误，并将新引导实际用于下一次生成。

生图后保留首轮复核 JSON 和回执。同批候选合成都未通过时，脚本保留可局部修正且待复核开口、路线和断段合计最少的一张。打开这张预览，沿原采样定位隔墙、门扇或家具。路径通过时也看 `detailsPath` 中的桌椅局部，逐边核对席位及桌端留空。转角需清线时先对照同坐标的原图，辨认虚线、标高和门边参考线。只清成图中确认多出的线或家具，误擦的原有线用 `restore` 贴回，再按首轮路线和净宽复查。确实读错原图时，按原图依据另存一套复核 JSON、引导和回执，写清原位置与新位置的区别，并把新引导用于下一次生成。仅要核对其它可行路线时，可另存诊断 JSON 并注明是图面复查，原回执仍用于交付校验。

## 净距与可用席位

- 净距量两侧实际边缘之间的最窄处，计入柱、门扇、椅区及其它占用。桌端到桌端、桌端到柱和可连续行走的净宽分别记录。以项目给定的要求或已说明的使用假设为准，查真实开口与两端到达。
- 按能进入、落座和起身的席位计数。靠墙活动椅检查拉椅空间，固定卡座检查实际进入方向。主要柜体检查站立取物及门扇、抽屉的使用空间，卫浴设备检查操作面和到达路径。
- 复用成图的坐标、边界、家具与障碍，截取相关局部，图元与宽度使用同一单位。优先按可靠 CAD 几何或明确标注的端点量取，区分净距、轴线距和外包尺寸。按图片换算时核对比例在量测方向和局部区域有效。像素量测用于判断相对关系，毫米净距需可靠定尺依据。
- 按需要同时发生的活动设置使用状态。例如核对抽屉打开时还能否通行，把拉开的实体抽屉加入该状态的障碍，再核对使用区。分时发生的使用状态可以分别检查。
- 有明确要求且实测达不到时，按实际差值调整可改区。资料只能支持估算或相对关系时，注明尺寸依据、不能定量的位置及待复尺项。

## 可选通路工具

使用已有 Python 与 Pillow。工具接收真实可用边界、同单位的障碍、路线或使用区，返回 JSON。

```text
python "<本技能目录>/scripts/layout_use_check.py" ".design-agent/use-check.json"
```

示例坐标用于说明接口，项目取值以实际图元和需求为依据。

```json
{
  "units": "mm",
  "boundary": [[0, 0], [5000, 0], [5000, 4000], [0, 4000]],
  "objects": [{"id": "cabinet", "rect": [100, 700, 700, 2500]}],
  "routes": [{"id": "entry-to-use", "from": [1000, 1000], "to": [4000, 3000], "width": 800}],
  "use_zones": [{"id": "cabinet-open-use", "rect": [700, 700, 1500, 2500]}]
}
```

- `boundary` 为实际可达区域的简单多边形。`objects` 的 ID 唯一，几何用 `rect: [x0,y0,x1,y1]` 或 `polygon: [[x,y],...]`。把穿行受限的区域和主要障碍计入；真实门口留出实际宽度。
- `routes.width` 取要验证的净宽，起终点跨过瓶颈，选在两侧的实际空地。端点是通行探针中心，到边界需要留半个探针宽度和误差余量。检查分辨率由工具返回，可按局部精度调整 `resolution`。
- `use_zones` 描述拉椅、柜前站立、开门和取物等区域。`ignore_objects` 只引用该使用区所属设施本体等实际允许重合的图元。路线仅按 `objects` 计算，需要同时避让的开启部件应放入 `objects`。
- `clear` 表示在所传几何和状态下留有数值误差余量，`blocked` 表示按当前输入仍受阻，`borderline` 表示栅格精度下结论待复尺。每条路线的 `widthTolerance` 是核对阈值用的数值余量，项目所需宽度仍为 `declaredWidth`。靠近阈值时，用可信图元或标注直接复尺再下结论。端点受阻先复核选点和实际开口。`ok:false` 时按错误修正输入或缩到相关局部。

工具仅检查已传入的图元与使用状态，最后仍需在实际成图确认保留项、图文、通路与可用性。法规或施工深度的核验依赖相应项目资料。
