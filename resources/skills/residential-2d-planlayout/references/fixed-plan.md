# 固定底图编辑

用于有用户底图且须保留结构或尺寸的任务。先明确保护对象和可改范围，一次完成预检。原图做最终图底层，生成图只提供允许变化的区域。首轮以原图为参考，只有确需提示编辑边界或易错位置时才传引导。对位、合成和验收共用原图坐标与回执。

合成前沿用底图一致的墙线和地面表现，保持家具完整落在可改区，门扇弧内地面与相邻区域一致。深底 CAD 有同几何坐标、同标注的清晰出图时，可按用户要的画法先导出底图并核对结构及尺寸，再从该底图建回执。只有位图时沿用其坐标和原结构线，并把可改区材质做成相容画法。看到块状底色、断墙、截家具或门弧遮挡时，检查候选与贴回分界，沿同一保护范围处理。

把确认的范围一次写入复核 JSON。可改区沿室内净边界取，完整容纳要变的家具、台面或洁具。把改区内的保留墙柱、原门窗、入户、固定设备、尺寸和标高写入 `locks`。尺寸和标高的保护覆盖原值、引线及两端，终验核对有无异地错误数值。范围外沿用底图。只把已确认可改的隔断和相接两侧加入改区，需要核验的门洞写进 `crossings`。不确定处原样保留。坐标集中查看一次。

原图有标识剪力墙的红色墨迹时，可先从原图制作等尺寸的线稿副本，仅将已确认的标记墨迹转换为灰黑，保留原位置、范围和覆盖像素，核对周边零变化后再冻结副本作为合成底层。无法可靠区分时保留原图并说明图例。临时引导色仅出现在生图输入。

```text
python -B "<Skill 路径>/scripts/plan-coordinate-view.py" --input-path "<原图>" --output-path ".design-agent/原图坐标.png"
```

`originalSha256` 用坐标回执中的值。`edits` 和 `locks` 都是形如 `[{"points":[[左,上],[右,上],[右,下],[左,下]]}]` 的原图多边形，可依实际凹凸增点。固定实心区全部确认后才加 `--protect-filled-regions`。只给关键占位写 `planPoints`，易被画断的家具用完整 `rect`。开门或去隔断写 `crossings`，`from` 和 `to` 紧贴两侧墙面，`width` 沿墙从要开的范围量取。入口与设备的相对位置易被画错时，先确认实际门洞，再给最容易错的 1–2 处加引线。[字段和拟设门洞](locked-plan-edit.md#登记前核对)

- 原图有可确认的架空梁虚线时，向相应线稿通路项加入 `"sourceBeamLines":[[左,上,右,下]]`。每个矩形只圈一条与通行方向横交的原虚线，沿虚线方向取至少 16 像素，厚度最多 6 像素，右边和下边为不含边界。验收只在采样时忽略位置与像素均未变化的原虚线墨迹，实际 PNG 保留原梁线。宽矩形、实线和改变后的像素仍参与检查。适用于可确认的线稿梁线，彩平或看不清的结构按实际位置待核。
- **冻结首次通过预检的回执。** 后续沿用这份回执。多版确有开口差异时，另建回执的引导与终验均带 `--initial-plan-receipt-path` 指向首轮回执。原必检开口的名称、采样位置、宽度、状态及梁线证据随回执保留。

需要引导或需要用脚本核对保护区时，用以下命令预检。整户和洄游共用这个入口。以 planPoints 检查原入户与关键落位，既有通路填 existingRoutes，拟建洄游填 plannedCircuits。阳台开口分别写 crossings。

```text
python -B -X utf8 "<Skill 路径>/scripts/fixed-plan.py" --original-path "<原图>" --review-path ".design-agent/复核.json"
```

预检返回 `guidePath` 和 `planReceiptPath`。只有引导需要呈现给生图时才上传，整户彩平可加 `--colored-plan`。旧门轨容易被照抄且已确认可拆时，可按[拟开口与洄游](layout-use-check.md#拟建洄游检查)先做去轨引导。提示词明确要保留的门墙，对可拆段写明位置及要保留的两个墙端。

使用引导生图时，先确认原尺寸、墙线和门洞清楚可辨，画幅、裁切范围、宽高与原图一致。发现标注遮挡或冲突时，按[生图标注](image-generation.md)调整标注。原图的全部保留要求共同决定保护范围。

先选功能成立且边界可对位的候选，再用以下命令以原图为底合成并检查锁定项及改区外像素。备选可用 `--alternate-candidate-path`。随后检查实际准备登记的 `verifiedPng`，包括受影响区域及邻接墙端、开口和完整家具。无法确认对位，或补救后仍不能同时保住几何和完整对象时，保留缺口说明，停止登记。

```text
python -B -X utf8 "<Skill 路径>/scripts/fixed-plan.py" --original-path "<原图>" --candidate-path "<首选候选>" --plan-receipt-path "<planReceiptPath>"
```

工具建立独立中间和交付路径。全题的补救与登记额度遵循 [Skill 主流程](../SKILL.md#复核与交付)。

## 局部恢复原图

布局和通路已经成立，且保真缺口限于几个原有图元时适用。对位结果可复用。有缩放或偏移时，用 `compose-plan-edit.py` 的 `--base-path` 指向原图，`--candidate-path` 指向生图，传入含原图定位范围的 `--regions-path`，取 `--aligned-preview-path` 输出作为对位候选。命令要求的 `--output-path` 为工作区中间件。核对问题处的墙端、门垛或尺寸界线都能对上。两图画法或局部几何不相容时，转回补救判断。

在原图坐标圈定各处最小完整范围。原尺寸带上数字、引线和端点，门窗带上原洞口、门框和该处误画痕迹。把互不冲突的范围放入同一修补 JSON 的 `repairs` 数组，每项填写 `{"type":"restore","rect":[左,上,右,下]}`。发现范围与用户要求新开的洞口、新布置的家具或需保留的台面相交时，先缩到仍能完整恢复的图元边界。重叠无法安全分离时，保留候选并按缺口判断补救。

对已对位至原图画幅和像素坐标的候选，用 `repair-plan-openings.py` 一次恢复。`--base-path` 指向对位候选，`--original-path` 指向原图，`--original-locks-path` 指向含 `originalSha256` 的保护 JSON，`--repair-path` 指向修补 JSON，指定 `--output-path` 并加 `--before-protection`。打开实际输出，核对恢复区与原图一致、邻接构件接合完整、原值在别处无错误重复。再对照修前候选，确认已通过的开口、通路、家具和台面完整。全区像素级保留要求仍按上面的固定底图回执核验。

## 贴回与清线

- **贴回按完整占位。** 在原图坐标对照未裁切候选与贴回图，查看每条裁切边、锁区和完整家具、洁具、台面的交点。候选完整而贴回后缺角或消失时，保留原墙、原尺寸标高和通行范围，将整件移到同一功能区内有余量的位置，或采用同批候选中已经完整落位的局部。确认原图依据后，可将裁切边纠正到实际可改净区内。连续台面按整组取用，接缝落在真实墙边、家具或材质边界。尺寸和标高文字、引线、两端及原构件保持原位。
- **清线按实际旧图元。** 先对照原图、未清线预览及开口两侧，区分旧隔断、轨道、标注、门槛、台面和洁具边线。只清已确认要拆且与保留图元无交叠的线段；小矩形可分别覆盖不同线段。新旧线叠在同一处时，从同批对位候选替换完整净区，或移动整件家具后再处理。保留线与旧线无法可靠区分时停止该局部修正，指出具体缺口。
- **验收用最终 PNG。** 对照一次此次改区，确认家具数量、外轮廓与台面衔接都完整，原标注无覆盖、改值或异地重复，门洞与主通路仍成立。自动通过只说明该回执检查的项目成立；受影响的物件未完成图面检查时不登记。

## 补救

先对照原图、对位候选和贴回图，锁住已通过的布置、开口和通路。贴回裁断时移动整件或换用同批完整局部。确认残线能沿旧图元安全分离时只清该段，保住邻接台面、家具和墙端。

局部结构或布局需要补生图时，从现有布局裁取问题区和少量连接上下文。先核待上传的图，清掉导致上轮失败的旧轨或引导色，保留拟接回的墙端与家具。工具列为 `unchangedSeparators` 的开口按未清处理。只有几何或布局整体失效且已纠正输入依据，才考虑整图补画。若唯一硬缺项是整图画法，补图用已确认合格的布局作参考，在实际请求中纠正画法，并要求所有合格的墙门、尺寸与家具位置沿用。整题仍共用一次追加额度。
