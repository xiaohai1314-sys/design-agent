# 固定底图编辑

清晰位图用原图保留墙柱、开口、尺寸和范围外内容。生图提供可改区的新布局。

## 登记前核对

1. **在原图确定范围。** 从原图识别固定墙柱、原入户、窗和必要通行净空。用 `write_file` 保存复核 JSON。`edits` 沿室内可改区域的实际凹凸边界，也覆盖只添家具的房间。`locks` 覆盖整段墙厚、墙端接缝、外窗内外线、入户符号及周边留白和既有通路净空。粗实墙与细墙线或窗框相接时，沿原图把相接端部完整划入保护带。固定入户处保留整个门洞、门垛、门扇开启弧和邻接标高。位置要保留的燃气表等设备连同符号及引线单独圈住。用 `planPoints` 的 `preserve` 矩形核对这些范围。空底图实心填充均为要保留的墙柱和入户符号时，启用 `--protect-filled-regions`。有可改实心对象时用[只读扫描和编译](source-layout-spec.md)选择需保留的编号。范围以原图坐标为准。
2. **先合成可对位的候选。** 生图以原图保留方向、比例和固定墙段。有关联语义的落位引线和通过通路预检的引导时，按对应步骤传图。候选返回后，把布局合适的候选按优先顺序交给合成命令。同批有第二张可用图时加 `--alternate-candidate-path "<同批第二候选>"`，首选对位或复核失败时自动尝试它。脚本核对原图身份、图幅、修改范围、锁定像素和指定开口，成功后写出 PNG。已有分布在改动区四周的同名角点时，可用 `--geometry-path` 指定当前候选的 `edits` 和 `anchors`。每个角点写 `{"base":[原图横坐标,原图纵坐标],"candidate":[候选横坐标,候选纵坐标]}`。
3. **打开整图验收。** 沿实际门洞检查房间数量、可达性、设备、相邻净空和合成接缝。先从原入户走到客餐厅，再逐一走到有独立围合要求的房间。门洞与门扇要有完整墙端衔接。用原图及复核 JSON 合成高反差线稿时，可加 `--inspect-seams` 检查经过门扇、家具或其它完整对象的接缝。`seamsToReview` 会给最多六处新增线条碰到接缝的位置，`rect` 为原图像素 `[左,上,右,下]`。对照原图和整图，区分接缝裁切与正常靠墙。若是裁切，把可改范围的接缝移到对象外的留白，保持原图保护区，优先用同一张候选重新合成。固定项已保住且只剩局部问题时，按下方处理。任何修补或重存后，重新复核实际要登记的 PNG。若还有硬条件偏差，写明位置、影响及概念稿状态。

复核 JSON 的最小格式如下，坐标为原图像素。`crossings` 无需采样时填空数组。深底浅线图加 `"background":"dark"`。需核对原开口时填写 `crossings`，保留双动线用 `existingRoutes`，拟建洄游用 `plannedCircuits`，见[连续通路与使用检查](layout-use-check.md)。

```json
{
  "originalSha256": "原图文件的SHA-256",
  "edits": [{"points": [[140, 140], [620, 140], [620, 440], [140, 440]]}],
  "locks": [{"points": [[360, 280], [410, 280], [410, 340], [360, 340]]}],
  "crossings": []
}
```

固定底图整户布置时，在 `planPoints` 中用 `point` 核对各房间的代表位置。对象可能碰到接缝时，用 `rect:[左,上,右,下]` 检查整个对象，右和下为不含的边界。需沿用的整段外窗、墙或门洞用 `"mode":"preserve"`。原图只有入户箭头时保留箭头，再单独检查新绘门扇的范围。例 `{"id":"厨房设备","point":[260,420]}`、`{"id":"门扇开启范围","rect":[260,390,328,455]}`、`{"id":"客厅外窗","rect":[360,120,515,138],"mode":"preserve"}`。对象位置看候选，坐标换回原图核对。脚本报范围遗漏时，按原图修正多边形，用同批候选及新的输出路径重跑，再打开整图检查。

需要比较两张合成图时，同时传 `--alternate-candidate-path` 和 `--alternate-output-path ".design-agent/同批备选合成.png"`。第一张通过几何检查的图写入 `--output-path`，第二张也通过时，报告的 `alternate.filePath` 给出其路径。打开两张通过的图，优先选门洞可达且设备完整的一张。局部对位或图面核对未通过时只处理受影响的内容。

```text
python -B -X utf8 "<Skill 路径>/scripts/compose-and-check-plan.py" --base-path "<原图>" --original-path "<原图>" --candidate-path "<候选图>" --review-path "<复核 JSON>" --output-path "布局方案.png"
```

## 整户落位检查

固定底图整户布置时，按拟定的房间和门逐项核对 `planPoints`。侧翼、凹口、厨房和玄关用 `rect` 覆盖贴边新增对象的完整外廓，例如入户新门扇、地柜及必要使用面。已有门窗和墙用 `preserve` 检查，矩形包括端部的浅线和墙窗交界。原图只有入户箭头且要新增门扇时，分别保护原箭头、检查门扇占位。每个范围按原图和拟定用法取点。通路分支沿用预检所用的同一份 `review.json`。其它整户任务在首轮生图前运行以下命令。原图上的实心区域均确认保留时，命令加 `--add-filled-locks`，合成用 `--protect-filled-regions`。实心锁保护确认的填充及其轮廓，细窗线和墙窗接缝仍需按原图圈定。

有必需床位、办公座或专用设备时，用现有 `rect`、`"showOnGuide":true` 加 `"guideLabel":"1.5m 床"` 把名称写在四角内。选最可能遗漏的几项，加注后直接用这张引导出图。窄框会自动缩小标签。若返回 `unshownFurnitureLabels`，把对应完整名称和使用要求补进本次生图提示词。位置以本户原图为准，最终图移除过程标签。合成后打开局部复核图，结合整图核对同名的实际床体、座位、设备和使用面。

```text
python -B "<Skill 路径>/scripts/compile-plan-requirements.py" "<用户原图>" "<review.json>" --check-plan-points
```

先按原图调整遗漏净区，再用同一份 JSON 合成。覆盖通过后，仍须在整图确认房间、门和设备实际存在。若整图少了已画在同批候选中的房间，先审查合成范围及裁切接缝，必要时用同一候选重新合成。

深底 CAD 空图转彩平时，室内门扇的黑底留白可由新地面填充。确认底色为纯黑、只含原门弧和线条的局部，可用 `"darkDoorLocks":[{"id":"书房门扇","rect":[438,550,556,664]}]` 固定原线条像素。坐标取自本题原图。门垛、墙端、外窗和外部入户范围仍按原图列入 `locks`，不得用线条保护替代这些范围。`darkDoorLocks` 与普通保护区一起参与预检、合成和验收。打开合成图查门弧是否完整、有无叠印候选自画的门扇，以及门口是否连通。

## 落位引线

门洞要错开或设备须在隔墙指定一侧时，先在原图取点。优先利用已有开口，柜或屏风形成进门转折，实际可走到门口和设备。要动既有分隔时，明确哪段获准改、实际开口与两侧净空。用一张原图副本标出新门洞、设备位置等最多三处，会保留的既有门可直接用文字定位。已有通路引导时把引线加到同一份复核 JSON。

`labels` 内每项用 `{"text":"冰箱在餐厅侧","x":710,"y":540,"anchor":[750,600]}`，文字放在空白处，引线末端放到对应位置。坐标与复核范围使用同一幅原图。用以下命令生成副本。

```text
python -B -X utf8 "<Skill 路径>/scripts/annotate-plan.py" --input-path "<未改原图>" --geometry-path "<含 labels 的 review.json>" --output-path ".design-agent/落位引导.png"
```

引导能读清原图时，作为唯一结构参考。提示词写明门从哪一侧进入、冰箱或设备落在哪一侧，成图去掉蓝色引线。外边界若需红线，沿整个平面外边界。复核时沿成图从入户走到厨房，检查真实门洞、柜体遮挡和设备开门空间。

冰箱等关键设备需要在隔墙指定一侧时，用 `planPoints` 的 `rect` 圈设备外廓，加 `"showOnGuide":true`。引导用四角标出已检查的占位，蓝字引线指到四角之间。出图语句写清设备与门、柜体及相邻房间的关系，成图去掉过程标记。门位变化涉及硬要求时，在引导中标到具体墙段，提示词写清墙两端和从哪一侧走入。按成图核对门洞两侧净空及路线。黑白线稿门洞难辨时，用[门洞采样](layout-use-check.md#位图门洞复核)定位横跨通路的线条，再放大辨认墙、门轨或柜体。

整户有落位引线时，以上命令加 `--check-plan-points --plan-receipt-path ".design-agent/落位回执.json"`，同一次执行先复核同一份文件中的 `planPoints`、可改区及原图哈希，再输出引导和回执。实心扫描结果均应保护时，同时加 `--protect-filled-regions`。合成时用 `--plan-receipt-path ".design-agent/落位回执.json"` 直接读取首轮范围及保护设置。已有通路引导时使用对应的 `--route-receipt-path`。

### 拟设门洞

门位改变涉及题意时，在同一份首轮复核 JSON 的 `crossings` 加 `{"id":"厨房新门","state":"proposed","from":[1020,680],"to":[1020,712],"width":70}`。用原图确认可调整的墙段，将两点沿通行方向放在墙两侧，`width` 沿墙量取，位置和宽度按本题改。用上述 `--check-plan-points --plan-receipt-path` 生成引导。浅蓝带标拟设开口，预检用原图锁区核对是否能打开。交彩平时加 `--colored-plan`，拟设开口默认使用相邻地面亮度。明确写了 `surface` 的开口沿用其设置。预检、贴回和最终验收使用同一份快照。

原图尚有已确认可改的分隔线时，在同一开口加 `"clearRect":[990,689,1050,702]`，按原图实际线段填写，避开两侧墙端。引导命令同时加 `--show-openings-cleared`。预检模拟清理，确认和保留范围无冲突且采样可通行后输出副本。整户落位引导的真实缺口不叠通行色块及指向缺口的引线，设备仍可标占位。以返回的 `guidePath` 作为唯一结构参考，原图用于合成和验收。提示词开头用房间方位定位缺口，从哪一侧进入、门扇向何处开，明确门洞中间留出连续空白。分隔性质仍需确认时，用通行带说明拟设位置及条件。

彩色底图上的尺寸字和材质线会让物理清墙预演失败。整户落位命令可同时加 `--keep-uncleared-openings`。预检只对已确认、范围合法但清除后仍有残线的分隔显示拟设蓝带，保留该开口在首轮回执内。用返回的 `guidePath` 出图，针对蓝带处要求画真实缺口。可改范围、墙柱保护和家具避让仍需通过预检。

已确认拆除整组门窗时，门扇弧线、窗边残线或与原分隔连在一起的旧房名可能伸出 `clearRect`。在整户落位开口中把同一构件的可移线段及随拆除失效的文字圈为 `clearAdjacentRects`，每个矩形与 `clearRect` 有交叠，并落在该版已确认的可改区。预检同时检查两侧家具占位和保留墙端。家具挡在开口上时先调整落位。清线只用于原图引导副本，成图仍使用原开口样带验收。

方案决定封闭旧门时，另加 `{"id":"封闭厨房原门","state":"closed","from":[936,546],"to":[969,546],"width":100}`。宽度覆盖原开口并伸入两侧原墙少许。引导用棕线标出拟补墙段，提示词要求两端接到原墙。合成同时检查新门有空白、旧门有连续线接近采样带两端。放大核对墙端接缝和新门开启净区。

按真实缺口或浅蓝带定位进入侧，写清旧门怎么处理和新门的开启状态。用户未指定门型时，选可用的开门方式，按实际门型画门扇。硬性开口需要可读的墙、门垛和通路时，出图沿用底图线稿，用户要求彩平则让开口及附近地面保持清楚且浅色。合成沿用同一回执。两张都没通过时，打开 `--review-preview-path` 和 `--review-details-path` 返回的图定位挡住门洞的线，详情坐标用于局部修正。放大辨认横线是门轨、墙或柜体，按实际开启状态表达。

## 只修有问题的局部

整图自动对位会优先用原有匹配。原图及候选都能辨认带凹凸折角的平面外轮廓时，也可由完整轮廓和分散角点独立确认对位。对位通过后仍看室内门墙、开口和家具完整性。仍不能对齐时，在两图各自的原像素坐标中选至少四个同名外墙折角、窗端或柱角，覆盖修改区上下左右。用 `write_file` 写 `anchors`，合成加 `--geometry-path` 并沿用原范围或回执。手工对位每张候选单独运行，使用该张图的同名点。局部仍偏离时，只贴回确实对齐的部分。

合成时加 `--review-preview-path ".design-agent/合成待复核.png" --review-details-path ".design-agent/局部复核.png"`。同批候选均未通过时，脚本保留已可靠对位且待复核开口、路线和断段较少的预览。命令仍以失败结束，报告给出预览与局部复核图的路径。打开局部复核图一次定位挡路的椅子、柜子、门扇或残墙，图块标题中的坐标是原图像素。沿用原复核 JSON、净宽及回执，在预览上修正具体问题，再复核完整图。通过复核时也可查看接缝局部，核对实际交付 PNG 的门扇与家具完整性。

返回预览且问题集中在一个局部时，下一步直接处理这张预览。局部图使用原图坐标，彩平开口会展示两边地面，橙圈标出闭环受阻点。从整图和局部图确认挡住开口的完整对象，再移动家具、补全门扇或清除残线。按 `repairArgs` 沿用已对位的预览和原回执，加 `--repair-path` 和新的 `--output-path` 一次复核。如需补救，在同批备选、局部贴回及生图之间一次选定合适方式，遵守 [Skill 主流程](../SKILL.md#复核与交付)的追加上限。

`repair.json` 可直接写 `{"repairs":[{"type":"move","rect":[340,420,440,510],"to":[350,434],"background":[455,470]}]}`。示例坐标按待复核图替换。修正支持 `restore`、`clear`、`move`，也兼容以这三项为顶层键的 JSON。移动取原预览的完整图块，避开其它图元。多处修正一起提交时，脚本依次恢复、清理、移动，再用同一回执复核。房名压到闭环时，把房名移到所属区域的空地或餐桌内部；核对移动后的文字和桌椅是否完整。

写入 `clear` 或 `move` 前按[贴回与清线](fixed-plan.md#贴回与清线)核对裁切边、保护区与整件物件。清线范围碰到台面、家具或洁具时，改用保留整件的候选局部或整件移动。

彩平有纹理时，`clear` 和 `move` 用 `backgroundFrom:[左,上]` 从同一张候选取同材质、无家具和文字的底纹。优先水平或竖直移动整件家具，脚本只补露出的条带。比如 `{"repairs":[{"type":"move","rect":[340,420,440,510],"to":[380,420],"backgroundFrom":[445,420]}]}` 会在背景取样点起复制 40×90 像素；`clear` 取与 `rect` 一样大的底纹。先从局部图看清家具及两侧余量，再把这组坐标写进 `repair.json`，用同一次合成核对原图和开口。放大看底纹是否接顺、家具是否完整。

报告给出 `turnCleanup` 时，工具已经模拟移除该孤立图块并复查闭环和开口。先看图确认矩形只覆盖完整的非必需对象，再把 `turnCleanup.repair` 直接写入 `repair.json`。必要家具、墙体或设备按实际用途局部处理。

开口没通过时，先在局部图辨认挡住开口的对象。`removableSeparatorRegions` 记录已核定的原轨道范围。确实回画原轨道或门扇残线时，按该范围及图面选定矩形，取同侧空白作背景修正。沙发、茶几或柜体占到开口时，用 `move` 把完整家具挪回室内净区，查看另一侧有无冲突。已恢复通行的图仍须核对桌椅、柜体和墙端没有被裁去一部分。沿首轮回执复核。

餐桌占位挤压原定转角时，若附近有完整净空，按桌和全部座椅的外框用 `move` 整组平移。原路径坐标和净宽照旧。移动后看各侧拉椅、开门和去相邻空间的路线，再登记。

桌椅或门扇可能被保护带裁断时，合成加 `--aligned-candidate-path ".design-agent/对位未裁切.png"`。若开口或路线未通过且有待复核预览，报告的 `alignedCandidatePath` 保留同一候选的未裁切图。对照预览确认裁切后，在未裁切图上圈完整桌椅或门扇，用 `move` 写入 `repair.json`。在下方恢复保护命令中，将该未裁切图作为 `--candidate-path`，加 `--repair-path "repair.json"`。工具先整组移动，再贴回原图，一次复查相同的回执及净宽。登记前确认家具完整及相邻使用距离。

- **已有原图线条能直接修正。** 用[开口与设备修正](../scripts/repair-plan-openings.py)按原图像素给 `rect:[左,上,右,下]`。`restore` 恢复原图局部。`clear` 清理局部残线，`move` 把完整可移动对象移到 `to:[左,上]`，两者均用 `background:[横,纵]` 指定候选空白取样。深底截图用原复核 JSON 的 `"background":"dark"`，保留其余区域的底色。调用时传 `--base-path`、`--repair-path`、`--original-path`、`--original-locks-path` 和 `--output-path`，再校验实际要交付的整图。

只需复查已有整图时，用[原图和开口校验脚本](../scripts/verify-plan-delivery.py)。若合成时加过 `--protect-filled-regions`，复查用同一份 JSON 并加 `--protect-filled-regions`，按同一原图重建实心保护区。合成时的 `--inspect-seams` 对比裁切前的对位图，`clippedStrokeContacts` 提示有新线条跨过裁切边界。放大对应矩形，核对门扇、家具与设备是否保留完整。保护区按像素中心逐像素核对，修改范围允许一像素的栅格化边缘误差。可加 `--stage` 保存通过后的原封 PNG 和哈希收据。

### 只清门洞残线

同一批两张都能对位但待修时，传 `--alternate-output-path` 和 `--review-preview-path` 可得到两张待修图。打开 `path` 和 `alternate.path`，先选房间、设备和家具齐全的一张。看到门洞两侧墙端、开启门扇和设备完整，仅有一条多余门槛线或轨道跨过通路时，按原图坐标只圈两墙端之间的这段残线，保留两侧墙和门扇。用已对位待修图相邻空白取底色，写 `{"repairs":[{"type":"clear","rect":[975,689,1028,694],"background":[1000,710]}]}`，替换为本题实际坐标。用对应的 `repairArgs` 加 `--repair-path` 再合成。放大确认门扇、门垛及邻近柜体没有因修线断开。

实际门洞与首轮位置不同时，按[方案变更复核](#方案变更复核)先核对原题、墙端和两侧通行。新样带覆盖两端实际门垛及门前门后，设计净宽与首轮对照。保留原来的可改范围和保护范围，两份回执都用于归档。若主要问题仍无法在局部解决，再为受影响的部位补图。

### 两端原墙续接

只剩已确认封闭的原开口、两端为同一直墙且没有必须保留的构件或设备时，优先在已经对位的候选上复用原墙线。`repair.json` 示例为 `{"repairs":[{"type":"infill","openingId":"封闭厨房原门","rect":[946,475,970,625]}]}`。矩形只圈旧开口及待替换的线，两端裁到相接的原墙内。`openingId` 引用首轮回执中 `state: closed` 的同名检查。工具比对原图与候选两端的墙截面，吻合后沿同一坐标续接。范围及两端按本题取点。

采用已有预览与[恢复原图保护命令](#恢复原图保护)，加 `--repair-path "repair.json"`，沿用首轮回执。实际成图检查两端接顺、新入口仍可通行，附近柜体和设备保持完整。两端截面不一致时查看原图和候选，按局部贴回流程处理。

### 贴回局部候选

待修整图中的门、隔墙或家具确需重画时，把 `crop: [左,上,宽,高]` 和这次贴回的 `edits` 写到同一份 `patch.json`，均用原图坐标。圈完整的对象、新位置和要补的地面。裁图比贴回范围大，四周带可辨认的固定墙角、门垛或窗端。用[底图标注脚本](../scripts/annotate-plan.py)先核对贴回范围，再从已对位整图裁出局部。沿用首轮回执。

```text
python -B -X utf8 "<Skill 路径>/scripts/annotate-plan.py" --input-path "<已对位待修整图>" --geometry-path "patch.json" --output-path ".design-agent/局部生图参考.png" --patch-original-path "<用户原图>" --initial-plan-receipt-path "<首轮回执>"
```

合成报告有 `localPatch.referenceImage` 时，这张局部参考图已导出。先看 `pasteRectInReference` 是否包住需改的完整墙段、家具及新落位，同时保留两端墙头。合适时直接以该参考图生图，命令里的两处 `patch.json` 均用 `localPatch.patchPath`，底图用 `localPatch.usePreview`。旧报告只有 `patchJson` 时，原样保存为文件。待修对象超出建议矩形时，在首轮许可内圈完整对象和新位置。沿用原 `crop` 或按需扩裁图，按原图坐标写 `edits` 并运行上方预检。生图提示写清要去的墙或门扇、家具新位置和四周需保留的物件，开口两侧留实际可通行地面。返回候选后用同一份局部参数贴回并复核整户。

```text
python -B -X utf8 "<Skill 路径>/scripts/compose-and-check-plan.py" --base-path "<同一张已对位待修整图>" --original-path "<用户原图>" --candidate-path "<局部候选>" --plan-receipt-path "<首轮回执>" --reference-crop-path "patch.json" --regions-path "patch.json" --output-path ".design-agent/布局方案.png" --review-preview-path ".design-agent/局部贴回待修.png" --review-details-path ".design-agent/局部贴回复核.png" --delivery-stage-path ".design-agent/可登记方案" --delivery-png-path "布局方案.png" --return-review
```

有同批备选时加 `--alternate-candidate-path`。通路引导的局部裁图可把首轮路线回执传给 `--initial-plan-receipt-path`，合成时用 `--route-receipt-path`。旧任务仅有复核 JSON 时以普通裁图准备局部，合成用首轮 `--review-path`。如果匹配点盖不住贴回范围，先判断是否裹进无关家具或空白。需人工取点时，找至少四个实际同名且包住整块修改的位置。移除 `--reference-crop-path` 和 `--regions-path`，在 `--geometry-path` 指定的 JSON 写原图坐标 `edits` 和原图到局部候选的 `anchors`。接缝直接放大查看。贴回后看实际门、墙端、连续通路及家具，复核通过再登记。

候选已画通，贴回后才出现断口时，先查贴回接缝。用同一候选把接缝移到通行样带外的地板留白，避开墙端、门洞和家具。沿用首轮回执复核。若接缝经过房名，把残字留在本次修整范围内一并处理。局部需要放大时用 `plan-coordinate-view.py --regions-path` 按原像素查看。

### 分块沿用同一底图

整张彩平的外墙角无法用同一变换对齐时，先确定哪些房间有能核对的门垛、柱或窗端。用原图或已可靠合成的部分作为整户底图。保留实际固定的墙窗和出入口，用完整室内范围取家具和地面，变动的分隔与两侧相连区域一起贴。已经对位且无需调整的房间保留在底图上。

沿用上方局部贴回命令，加 `--compose-part --inspect-seams`，省去 `--delivery-stage-path` 和 `--delivery-png-path`。第一次 `--base-path` 为原图，后续指向上一块合成后的整户图。`--original-path`、首轮回执与保护范围一路相同。`--regions-path` 写本次一块的原图坐标，`--reference-crop-path` 对应生成本候选时使用的原图裁切。自动对位失败而该块四周仍有可靠同名点时，单张候选可把 `--reference-crop-path` 换成 `--geometry-path`，只写这块的四对或更多对应点，沿用原有误差和覆盖要求。输出用来继续拼接。完成后按原回执核对全屋所有门洞、通路和实际家具，再登记。某块缺可靠对应点时，沿用原图该部分，针对缺口单独补图。

## 恢复原图保护

`changedProtectedRegions` 列出有像素差异的墙窗保护区和坐标。先确认保护带沿实际墙窗边缘并包含抗锯齿线。已对位的图经局部调整后需要恢复保护时，按下面的命令重新合成。沿用复核 JSON，把已有的修改只贴回可改区，再检查输出及接缝。仅用于已经完成对位的图，原生候选仍按普通流程对位。

```text
python -B -X utf8 "<Skill 路径>/scripts/compose-and-check-plan.py" --base-path "<原图>" --original-path "<原图>" --candidate-path "<已对位并局部修正的图>" --review-path "<复核 JSON>" --output-path "<新的登记 PNG>" --reapply-original-protection --inspect-seams
```

带引导时，上面命令用实际送入生图的 `--plan-receipt-path "<落位回执>"` 或 `--route-receipt-path "<通路回执>"`，合成自动读取其旁边留存的复核范围和实心保护设置。其它任务沿用 `--review-path` 和已启用的 `--protect-filled-regions`。待复核预览只需移除残线、移家具或恢复局部时，把修正坐标写成新的 `repair.json`，加 `--repair-path "<repair.json>"`。同一次执行会修正预览、贴回原图并复核。若还有通路问题，可加 `--review-preview-path` 保存新的待复核图。原图有其它应保留但初次未锁住的门时，可在本次修正中用 `restore` 贴回完整原门和相接墙端，沿用首轮开口和路线。若改名或标注会触及原图锁定区或可改区外，把新图名放在文件名或随图说明里。

```text
python -B "<Skill 路径>/scripts/verify-plan-delivery.py" "<原图>" "<整图>" "<复核 JSON>"
```

### 登记文件复核

有开口、通路硬条件或最后又修过图时，沿用生图使用的回执，原样归档实际复核的 PNG。用 `deliver` 登记 `verifiedPng` 路径。没有引导时在候选 PNG 后直接传原复核 JSON，并沿用实心保护设置。

```text
python -B "<Skill 路径>/scripts/verify-plan-delivery.py" "<原图>" "<要登记的PNG>" --guide-receipt "<首轮回执>" --stage ".design-agent/可登记方案"
```

仍有必需功能或开口不成立时，说明失败位置和影响，候选保留在工作区。成图另有几何或使用问题也据实交代。复核通过后如再改图，重新复核修改后的文件。

### 方案变更复核

同一布局沿用首轮回执和样带。候选自行换了门位、动线或设备时，先对照原题逐项确认替代方案，例如入户和厨门实际错位、冰箱符号确实在餐厅侧、厨房门打开后仍可进入。保留原图锁区与已核定的改动边界。另排确有必要时，记录改变的空间关系，按整个实际开口以及需封闭的旧口取样。固定底图用 `annotate-plan.py` 生成新引导时，同时传新的 `--plan-receipt-path` 和 `--initial-plan-receipt-path "<首轮回执>"`，先核对新方案坐标是否越界，再提交生图。实图的设备、房间或通路仍有硬缺项时不登记该候选。

使用 `--guide-receipt "<新回执>" --initial-guide-receipt "<首轮回执>" --stage "<登记目录>"` 复核实际要登记的 PNG。命令会核对新回执是否扩大可改区或减少保护范围，并按新布局的样带验收实际开口和封墙。用户明确改变改动范围时，从原图为本轮重新预检。
