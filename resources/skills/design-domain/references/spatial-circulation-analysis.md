# 空间与动线分析

只在任务需要精确判断相邻、包含、入口、路径连续性、人车流线、疏散或在既有图面落置空间标注时读取本参考。概念首版、氛围表达和普通文件制作不加载。

## 一、建立空间工作包

绘制或判断前，用当前任务目标和已确认事实建立一份短小台账：

1. 基准底图：最终表达需要保留或对照的完整当前项目图面，记录来源、原始尺寸、方向和指纹。
2. `semantic_authority`：证明空间名称、入口名称、用途、设计条件和明确约束。
3. `geometry_source`：证明锚点、边界、道路、空间轮廓和连续路径；记录坐标空间与定位方式。
4. `style_reference`：用户指定的表达参照，只约束表现方式。
5. 证据空格：逐项写明尚缺的对象、关系和位置；只为这些空格补读来源。

基准底图和其他几何来源不是同一坐标空间时，必须有可验证变换才能把坐标落到底图。透视图、效果图和局部氛围图不能证明平面路径，除非它们同时提供可核验的平面投影和坐标关系。

## 二、空间证据的确定性

- `direct_pixel`：原始像素中直接可见，坐标落在声称对象或连续几何上。
- `trusted_geometry`：CAD 或其他可信解析保留了原生实体、Layout、bbox、文字或尺寸，并能定位回原件。
- `derived`：由多个已确认事实推导出的专业判断，必须列出依据。
- `uncertain`：像素、坐标、语义或来源归属仍无法确认。
- `contradicted`：结构化记录与原始像素或另一权威来源直接冲突。

提取脚本只能给出候选，不能自行把候选升级为项目结论。登记路径或锚点前至少核对：坐标是否落在声称对象上、折点是否沿同一连续几何、几何专业含义是否与标签一致、坐标是否属于登记的来源空间。任一项看不清就保留 `uncertain`。

## 三、空间、功能和相邻关系

建立最小空间模型：

1. 空间节点：名称、功能、使用频率、开放程度和必须条件。
2. 相邻关系：直接相邻、便捷联系、应隔离或当前无法判断。
3. 出入口：使用人群、服务对象、到达路径与可见性。
4. 路径：起点、终点、途经节点、连续性、交叉和障碍。
5. 边界：不可越界、控制边界、结构或设备限制。

检查顺序：

- 先查硬冲突：路径中断、跨越不可通行边界、入口落在错误对象、路线不在已确认可行空间。
- 再查高频关系：高频联系空间是否被不必要拉远，应隔离空间是否直接冲突。
- 最后查体验：识别性、转折复杂度、拥堵、视线与空间层次。

建议必须明确落到“移动哪个空间、调整哪段路径、补核哪个锚点或修改哪张图”，避免只说“优化动线”。

## 四、路径与坐标

- 路径只由已确认的入口、可行几何和连续段组成。边界线、轮廓线、景观线和未知线不能因形状连续就当作交通路径。
- CAD 中的文字、尺寸和实体要保持 Layout 与图层归属；跨 Layout 或跨文件拼接必须有明确变换。
- 图像坐标记录原始宽高、裁剪区域和缩放；局部图坐标必须可还原到原图。
- 若来源只支持概念级关系，输出应标为 schematic，不给出伪精确尺寸或坐标。
- 结构化记录与原始像素冲突时，回读冲突局部并更新事实；不能用最终成品的位置反向证明记录正确。

## 五、在既有图面上表达

- 需要保真叠加时，从基准底图真实像素和原始尺寸创建画布，只叠加独立图层；不得重绘、拉伸或用空白示意替换底图。
- 新增路径、节点和标签不得遮挡关键边界、图例、尺寸和原生文字。
- 每个新增元素绑定到来源证据或明确标为设计建议；建议性路线与现状事实在视觉上区分。
- 坐标来自其他来源时，只有 sidecar 中存在已验证变换才可直接落到底图；否则只作定位线索。

需要可审计空间关系时，由任务按需显式生成 `<artifact>.spatial-evidence.json`；运行时不会自动登记该 sidecar。文件至少包含：

- 原件与成品 SHA256；
- 原始坐标空间、成品坐标空间和 transform；
- 锚点来源、坐标、确定性与 locator；
- 每条相邻、包含、方向或路径关系及其证据 ID。

然后使用 CAD Skill 的 `spatial_verify.py` 做确定性验证。sidecar 与验证结果是审计件，不替代正式图件。

## 六、交付前专业检查

1. 基准底图是否完整保留，指纹和尺寸是否与台账一致。
2. 每个必需锚点、路径和空间关系是否有当前来源证据。
3. 新增路径是否沿已确认可行几何，是否跨越不可通行边界。
4. 标签是否指向正确对象，是否遮挡原图关键信息。
5. 坐标变换、锚点残差和 sidecar 关系是否通过确定性验证。
6. 不能从当前原件核实的项目是否明确标为 uncertain/blocked，而不是以整体观感代替。

`spatial_verify.py` 是任务显式调用的确定性校验脚本，不是自动中间件，也不替代专业内容判断。只有用户明确要求独立专业评审时，才把原件、sidecar 和实际成品交给隔离评审能力；主执行模型的自述不能当作评审证据。
